M1Что такое облако

Облако это аренда чужих компьютеров через интернет. Берёшь сколько надо, платишь только за то, что используешь.
  • IaaS (Infrastructure as a Service, инфраструктура как услуга): дают голый сервер. Пример: EC2.
  • PaaS (Platform as a Service, платформа): ты кидаешь только код. Пример: Elastic Beanstalk.
  • SaaS (Software as a Service, готовая программа): просто пользуешься. Пример: Gmail.
  • Модели развёртывания: Cloud (всё в облаке), Hybrid (облако + свой сервер), On-premises (всё своё, private cloud).

6 плюсов облака (часто спрашивают)

  • CapEx → OpEx (Capital Expense, разовые покупки → Operational Expense, текущие траты): не покупаешь железо заранее.
  • Экономия на масштабе: у AWS миллионы клиентов, поэтому дешевле.
  • Не надо угадывать мощность: добавил или убрал сервера за минуты.
  • Скорость: сервер за минуты, а не недели.
  • Не тратишь деньги на свой дата-центр (ДЦ).
  • Глобально за минуты: запустился в любой точке мира.

Управлять AWS можно тремя способами: Console (сайт), CLI (Command Line Interface, команды в терминале), SDK (Software Development Kit, библиотеки для кода). Все они ходят через API (Application Programming Interface).

CAF (Cloud Adoption Framework, план перехода в облако): 6 перспектив. Бизнес: Business, People, Governance. Техника: Platform, Security, Operations.

M2Деньги и счета

Платишь за 3 вещи: вычисления, хранилище и исходящий трафик. Входящий трафик бесплатный.
  • Чем больше берёшь и чем дольше резервируешь, тем дешевле. Reserved: All Upfront (всё вперёд) дешевле, чем Partial, а Partial дешевле, чем No Upfront.
  • TCO (Total Cost of Ownership, полная стоимость владения): сравнить, сколько стоит свой ДЦ против облака.

M3Глобальная инфраструктура

Регион это город, AZ это отдельные здания дата-центров в этом городе, edge location это маленькая точка кэша рядом с пользователем.
  • AZ (Availability Zone, зона доступности): изолированные друг от друга ДЦ. Упал один, другие работают. Поэтому для надёжности кладём ресурсы в 2+ AZ.
  • Как выбрать регион (4 критерия): законы о данных, близость к пользователям (задержка), есть ли нужные сервисы, цена.
  • Edge location: точка, где CloudFront хранит копию контента ближе к пользователю.

M4Безопасность

AWS отвечает за безопасность самого облака, ты за то, что положил в облако.
Ловушка: ОС на EC2 патчишь ты. ОС под RDS патчит AWS. Чем "выше" сервис (RDS, Lambda), тем меньше твоей ответственности.

IAM: кто что может

IAM (Identity and Access Management, управление доступом).

  • User: человек или программа, постоянный логин. Group: набор users, права даём группе. Role: временные права, например EC2 читает S3 без ключей. Policy: JSON-документ с правами.
  • По умолчанию всё запрещено. Явный Deny всегда сильнее Allow.
  • Least privilege: давать минимум прав.
  • Доступ: programmatic (Access Key для CLI и SDK) и console (логин и пароль). MFA (Multi-Factor Authentication, второй код с телефона).
  • Root user: главный аккаунт. Включить MFA, удалить access keys, в работе не использовать. Только root меняет support plan и закрывает аккаунт.

M5Сеть и VPC

VPC это твоя личная закрытая сеть в AWS. Внутри неё подсети: публичные (есть выход в интернет) и приватные (нет).

VPC (Virtual Private Cloud, виртуальная частная сеть). Такую схему мы строили в лабе 2.

  • CIDR (Classless Inter-Domain Routing, запись размера сети): /16 = 65 536 адресов, /24 = 256, /28 = 16. Меньше число после слэша = больше сеть.
  • VPC: от /16 (самая большая) до /28 (самая маленькая). VPC на весь регион, подсеть (subnet) в одной AZ.
  • AWS забирает 5 IP в каждой подсети: в /24 остаётся 256 − 5 = 251.
  • IGW (Internet Gateway): дверь VPC в интернет. NAT Gateway (Network Address Translation): даёт приватной подсети выйти наружу (скачать обновления), но внутрь никого не пускает. Стоит в public subnet.
  • Route table: таблица "куда отправлять трафик". Main route table создаётся сама.

Остальное в сети

  • VPC Peering: соединить 2 VPC. Transit Gateway: хаб для многих VPC.
  • VPN (Virtual Private Network): шифрованный туннель через интернет. Direct Connect: отдельный физический кабель от твоего ДЦ до AWS.
  • VPC Endpoint: ходить в S3 без интернета. Elastic IP: постоянный публичный IP.
  • Route 53: DNS (Domain Name System, превращает site.com в IP). Политики: simple, weighted (по весам), latency (ближайший по задержке), failover (запасной сайт), geolocation (по стране), geoproximity, multivalue.
  • CloudFront: CDN (Content Delivery Network, раздача контента с ближайшей точки).

M6Compute: сервера

EC2 это виртуальный сервер в аренду. Lambda это код без сервера. Beanstalk это "закинул код, остальное сделает AWS".

EC2 (Elastic Compute Cloud). Что выбираешь при запуске (лаба 3):

  • AMI (Amazon Machine Image): шаблон с ОС и программами.
  • Название типа t3.large: t = семейство, 3 = поколение, large = размер.
  • Семейства: t, m обычные; c мощный процессор (Compute); r, x много памяти (RAM); i, d быстрые диски; p, g видеокарты (GPU) для ML и графики.
  • Состояния: pending → running → stopping → stopped → terminated (удалён навсегда). Сменить тип можно только после stop. От случайного удаления защищает termination protection.

  • Lambda: код по событию, без сервера (serverless). Платишь за запуски и время. Максимум 15 минут на запуск.
  • Elastic Beanstalk: закидываешь код (zip), AWS сам делает EC2, балансировщик, автомасштабирование.
  • Контейнеры (Docker): ECS (Elastic Container Service), EKS (Elastic Kubernetes Service), Fargate (контейнеры без своих серверов), ECR (Elastic Container Registry, склад образов).

Диски (лаба 4)

  • EBS (Elastic Block Store): диск для одного сервера, в той же AZ. После stop данные остаются. Бэкап = snapshot, хранится в S3.
  • S3 (Simple Storage Service): хранилище файлов-объектов, имя бакета уникально во всём мире, по умолчанию приватно.
  • EFS (Elastic File System): общая папка для многих серверов.
